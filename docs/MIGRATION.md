# WRX controller migration audit

Authoritative baseline: [`351e770`](https://github.com/DylanKral/wrx-ble-controller/commit/351e770), the entire 994-line `index.html`. A byte-for-byte copy is retained in `tests/fixtures/original-v8.2.html` and the original remains recoverable through Git. It is a test fixture only: Vite publishes only `dist`, which does not contain the old application. The work stays in this repository on `feature/react-migration`.

## Subsequent preset correction

At the user's request, the active Custom library now contains 10 fixed presets. Blue Overlap, standalone Chase, and standalone Flash were retired. Overlap · 1.30s cut now repeats exactly Mode 7 for 1300 ms → Mode 8 for 1300 ms, with no intervening color step. The Basic library is unchanged. Historical definitions remain available only to storage migration so old fixed slots cannot reappear as personal profiles and original user edits can still be recovered. The baseline audit below describes the original migration before this requested change.

`wrx-home-tab-change` is an old DOM event name, not a storage key. React state replaces this event. New `wrx-dream-before-react-v9` archives raw studio data once, best effort without preventing valid data from loading when quota is full. `wrx-dream-schema-version` records 9 after a successful user edit. Malformed studio/legacy JSON is surfaced and left untouched; initialization never writes normalized defaults over it. Older edited fixed slots are archived as `saved-edit-*` personal profiles. Old reassigned or renamed fixed buttons are preserved as additional assignments while the thirteen fixed buttons remain available. Versioned migration functions are isolated and unit tested. Complete configuration export includes **all** raw `wrx-*` keys, including unknown future keys; restore validates entries and rolls back writes on failure. Localhost has separate browser storage; existing production data becomes available at the unchanged production origin.

### Protocol

Write service FFD5, characteristic FFD9. Notification service FFD0, characteristic FFD4 are known and exported. The original never subscribed to notifications or interpreted completion events; the migration likewise does not invent any. Both services are requested as optional permissions for manual selection. Exact mode bytes `9E 00 [mode−1] 81 98 00 E9` and RGB bytes `56 RR GG BB 00 F0 AA` are preserved. Mode 4 and static blue have exact-packet tests.

### Deliberate correctness fixes

- All normal commands share one queue across pages; calibration shares per-device write exclusion and retains its skip-rather-than-queue stress-test behavior. Stop + Red aborts calibration as well as profile/favorite scheduling, waits for an existing write, and discards cancelled queued steps. In-flight radio operations cannot be recalled.
- One-pass sequences now keep their status active for the final step's requested dwell; the old studio cleared browser status immediately after the last write. Command values, dispatch offsets and physical last effect remain the same.
- A profile whose steps all have zero duration cannot loop indefinitely. Individual zero-duration steps remain supported.
- Unexpected disconnection cancels studio playback as well as favorite/calibration timers. The old studio did not cancel its loop until its next failed write.
- Unchanged fixed-button reordering survives refresh; overridden old fixed assignments are preserved rather than silently reset.

## Validation and remaining physical checks

Run `npm run typecheck`, `npm test`, `npm run test:e2e`, and `npm run build`. Tests compare all actual fixed profiles, Basic definitions, factory calibration values, and all calibration test offsets against the archived source. Browser tests use an explicit mock injected only into the test browser. The production bundle contains the real Web Bluetooth implementation.

Automated tests establish browser command behavior; they do not verify physical BLE radios or LED timing. Android Chrome and iOS Bluefy must still be tested with the actual paired lights. Check side identity, both-controller Mode 4/blue/red writes, full and early transitions, internal modes, same-mode retrigger behavior, calibration screen/video alignment, disconnect/recovery, and background cancellation. iOS may suspend JavaScript or require another user gesture to reconnect. Reopening this origin gives existing permissions their best chance of remaining available; it cannot override browser policy.

Deployment remains on the existing GitHub Pages origin and path. CI builds and tests feature pushes and PRs; deployment only runs for main after validation. No service worker is installed. Do not mark physical testing complete from mocks.
